더 자세한 설명은 [`week4-study.md`](week4-study.md), 직접 조작해 보는 예제는 [`camera-study.html`](camera-study.html)에 있습니다.

> **한 줄 요약**: 카메라도 행렬이다. **뷰 행렬 V**는 "어디서 어디를 보나", **투영 행렬 P**는 "얼마나 넓게, 원근감은 어떻게"를 정한다. 최종 식은 `gl_Position = P · V · M · 위치`.

---

## 1. 점이 화면에 도착하는 5단계

| 단계 | 계산 | 뜻 |
|---|---|---|
| 모델 → 월드 | $M p$ | 물체를 세계에 놓기 (2주차) |
| 월드 → 뷰 | $V p$ | **카메라 기준**으로 다시 적기 |
| 뷰 → 클립 | $P p$ | (x, y, z, w) 클립 좌표 |
| 클립 → NDC | $(x,y,z)/w$ | **원근 나눗셈**, 결과는 −1~1 |
| NDC → 화면 | 뷰포트 변환 | 픽셀 위치 |

- 카메라 좌표계: 눈이 원점, 오른쪽 +x, 위 +y, **바라보는 방향 −z**입니다. 그래서 카메라 앞의 점은 **z < 0**입니다.
- `gl_Position`에는 **클립 좌표**를 넣습니다. 클리핑($-w\le x,y,z\le w$)과 w 나눗셈은 GPU가 합니다. **셰이더에서 w로 나누지 마세요.**

```glsl
gl_Position = uProj * uView * uModel * vec4(aPos, 1.0); // 오른쪽부터: M(배치) → V(카메라 기준) → P(투영)
```

## 2. 뷰 행렬 = 카메라 배치의 역행렬

- 카메라를 물체처럼 세계에 놓는 행렬을 C라 하면 $\boxed{V=C^{-1}}$입니다. 카메라를 오른쪽으로 옮기면 세계가 왼쪽으로 가는 것과 같습니다.
- $C=TR$이면 $V=R^{-1}T^{-1}$입니다. **위치를 먼저 빼고, 회전을 거꾸로** 적용합니다.
- 예: 카메라가 (0,0,5)에서 −z를 보면 원점 물체의 뷰 좌표는 (0,0,−5)입니다. 카메라를 +x로 2 옮기면 (−2,0,−5)가 되어 물체가 왼쪽으로 갑니다.

## 3. lookAt(eye, target, up)

$$\hat z=\frac{e-t}{\lVert e-t\rVert},\quad \hat x=\frac{up\times\hat z}{\lVert up\times\hat z\rVert},\quad \hat y=\hat z\times\hat x$$

```js
function lookAt(eye, target, up) {                       // 뷰 행렬 V 만들기 (열 우선 16칸)
  const z = normalize(sub(eye, target));                 // 카메라 +z = 시선의 반대 방향
  const x = normalize(cross(up, z));                     // 카메라 +x(오른쪽) = up × z
  const y = cross(z, x);                                 // 카메라 +y(진짜 위) = z × x
  return new Float32Array([                              // WebGL은 한 '열'씩 저장
    x[0], y[0], z[0], 0,                                 // 1열
    x[1], y[1], z[1], 0,                                 // 2열
    x[2], y[2], z[2], 0,                                 // 3열
    -dot(x, eye), -dot(y, eye), -dot(z, eye), 1,         // 4열: 카메라 위치를 빼는 효과
  ]);                                                    // 행렬 끝
}                                                        // (sub, dot, cross, normalize는 2주차 함수)
```

- `up`은 "대략 위"라는 힌트입니다. 실제 위쪽 축은 외적으로 다시 계산합니다.
- `eye == target`이거나 **up이 시선과 평행**하면 축을 정할 수 없습니다. 궤도 카메라의 상하 각도를 ±89°로 제한하세요.

## 4. 직교 투영 vs 원근 투영

| | 직교 (ortho) | 원근 (perspective) |
|---|---|---|
| 보이는 공간 | 직육면체 | **절두체** (꼭대기를 자른 피라미드) |
| 먼 물체 | **같은 크기** | **작게** |
| 쓰임 | 치수 비교, 도면 (정면·측면·평면도) | 자연스러운 3D 화면 |
| 설정 | left, right, bottom, top, near, far | **fovy**(수직 시야각), **aspect**(가로/세로), near, far |
| w_clip | 1 | $-z_v$ (= 깊이) |

```js
const aspect = canvas.width / canvas.height;             // 화면 비율. 매번 계산해야 찌그러지지 않음
mat4.perspective(proj, 60 * Math.PI / 180,               // 원근: 시야각 60°를 라디안으로
                 aspect, 0.1, 100);                      //   화면비, near, far
const h = 4;                                             // 직교: 세로로 담을 범위의 절반
mat4.ortho(proj, -h * aspect, h * aspect, -h, h,         // 좌우 = 세로 × 화면비
           0.1, 100);                                    //   near, far
```

- **원근**: $y_{ndc}=s\cdot\dfrac{y_v}{-z_v}$ ($s=1/\tan(\text{fovy}/2)$). 깊이로 나누므로 멀수록 작아집니다. 행렬은 w에 깊이를 담고, 나눗셈은 GPU가 합니다.
- **직교**: x·y 계산에 z가 없어 멀어도 크기가 같습니다. 확대하려면 카메라를 옮기지 말고 **h를 줄이세요**.
- 절두체 단면 크기는 깊이 d에서 반높이 $h(d)=d\tan(\text{fovy}/2)$입니다. 물체를 화면에 맞추는 거리를 계산할 때 씁니다.
- 강의 예제 값 (`camera-study.html`로 확인함):
  - 원근 (FOV 90°, n=1, f=9): 점 (1,1,−3) → 클립 (1,1,1.5,3) → NDC (⅓,⅓,0.5)
  - 직교 (x ±4, y ±2, n=2, f=10): 점 (2,1,−6) → NDC (0.5,0.5,0)

## 5. 헷갈리기 쉬운 것

| 조작 | 바뀌는 행렬 | 결과 |
|---|---|---|
| FOV 줄이기 | P | 확대. 물체끼리 크기 비율은 그대로 |
| 카메라 전진 | V | 가까운 물체가 훨씬 더 커짐 |
| near만 바꾸기 | P | 앞부분이 잘림. 크기는 그대로 |

- near·far는 **near는 가능한 크게, far는 필요한 만큼만** 정합니다. near가 너무 작고 far가 너무 크면 깊이 정밀도가 부족해 **Z-fighting**(깜빡임)이 생깁니다.
- 분할 뷰에서는 각 뷰 영역의 **폭/높이**를 aspect로 써야 합니다.
