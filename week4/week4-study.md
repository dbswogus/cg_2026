## 1. 카메라도 행렬입니다

### 1-1. 약속한 좌표계

이 수업은 **y-up, 오른손 좌표계, 열벡터**를 사용합니다(3주차와 같음).

**카메라 좌표계(뷰 좌표계)** 는 카메라를 기준으로 한 좌표계입니다.

- 눈(카메라)이 **원점** `(0, 0, 0)`
- 화면 오른쪽 = **+x**, 화면 위쪽 = **+y**
- 카메라가 바라보는 방향 = **−z** ← 가장 헷갈리는 부분입니다!
- 그래서 **카메라 앞에 있는 점은 뷰 좌표의 z가 음수**입니다. 예를 들어 5만큼 앞에 있으면 z = −5입니다.

### 1-2. 점 하나가 화면에 도착하기까지 5단계

| 단계 | 계산 | 쉬운 말 |
|---|---|---|
| 모델 → 월드 | $p_w = M p_m$ | 물체를 세계에 배치한다 (2주차) |
| 월드 → 뷰 | $p_v = V p_w$ | 같은 점을 **카메라 기준**으로 다시 적는다 |
| 뷰 → 클립 | $p_c = P p_v$ | 투영·클리핑에 쓸 4차원 좌표(x, y, z, w)를 만든다 |
| 클립 → NDC | $(x_c, y_c, z_c) / w_c$ | **원근 나눗셈**: w로 나눠 −1~1 범위로 정규화 |
| NDC → 화면 | 뷰포트 변환 | −1~1 좌표를 실제 픽셀 위치로 바꾼다 |

모두 합치면 다음과 같습니다.

$$p_c = P\,V\,M\,p_m$$

행렬은 **오른쪽부터** 적용됩니다. M을 먼저 곱하고, 그다음 V, 마지막에 P입니다.

```glsl
// 버텍스 셰이더 안의 한 줄 (GLSL)
gl_Position = uProj * uView * uModel * vec4(aPos, 1.0); // aPos(모델 좌표)에 M → V → P 순으로 곱한 결과 = 클립 좌표
//            ^P      ^V      ^M      ^ 위치 (w=1: '점'이라는 뜻, 이동 변환이 적용됨)
```

### 1-3. 주의: 클립 좌표와 NDC는 다릅니다

- `gl_Position`에 넣는 값은 **클립 좌표**입니다. 아직 −1~1 범위로 나눈 값이 아닙니다.
- WebGL이 알아서 다음 두 가지를 해 줍니다.
  1. **클리핑**: $-w_c \le x_c, y_c, z_c \le w_c$ 범위 밖을 잘라냅니다. 경계에 걸친 삼각형은 안쪽 부분만 남습니다.
  2. **원근 나눗셈**: x, y, z를 w로 나눕니다.
- 그러니 **셰이더에서 직접 `w`로 나누지 마세요.** 그러면 GPU가 한 번 더 나누게 됩니다.

## 2. 뷰 변환 — 카메라 배치의 역변환

### 2-1. "카메라를 옮긴다" = "세계를 반대로 옮긴다"

기차 창밖을 보면 기차는 가만히 있고 풍경이 뒤로 지나가는 것처럼 보입니다.
화면에 찍히는 결과는 **카메라와 물체의 상대적 위치**로만 정해지기 때문입니다.

카메라를 하나의 물체처럼 세계에 배치하는 행렬을 **C**(카메라의 월드 행렬)라고 하겠습니다.

- C: 카메라 좌표 → 월드 좌표 ($p_w = C p_v$)
- 거꾸로 월드의 점을 카메라 좌표로 가져오려면 C를 **되돌리면** 됩니다.

$$p_v = C^{-1} p_w \qquad\Rightarrow\qquad \boxed{V = C^{-1}}$$

모델 변환은 물체를 세계에 **놓는** 일이고, 뷰 변환은 세계를 관찰자 기준으로 **다시 적는** 일입니다.
이렇게 같은 변환을 반대 방향으로 해석하는 관계를 강의에서는 **쌍대성(duality)** 이라고 부릅니다.

> 주의: V는 **카메라의** 월드 행렬의 역행렬입니다. 장면 속 행성 같은 아무 물체의 M을 뒤집는 것이 아닙니다.

### 2-2. 순서도 반대로

카메라를 회전 R 후 이동 T로 배치했다면 다음과 같습니다.

$$C = T R, \qquad V = (TR)^{-1} = R^{-1}\,T^{-1}$$

옷을 입을 때 "속옷 → 겉옷" 순서였다면 벗을 때는 "겉옷 → 속옷" 순서인 것과 같습니다.
→ **카메라 위치를 먼저 빼고**, 그다음 **회전을 거꾸로** 적용합니다.

### 2-3. 숫자로 확인

| 상황 | 원점 `(0,0,0)`에 있는 물체의 뷰 좌표 |
|---|---|
| 카메라가 `(0,0,5)`에서 −z 방향을 봄 | `(0, 0, −5)` → 카메라 **앞** 5만큼 |
| 카메라를 오른쪽으로 2 이동 (`(2,0,5)`), 방향은 그대로 | `(−2, 0, −5)` → 물체는 화면에서 **왼쪽으로** 2 이동 |

회전이 없을 때 뷰 변환은 "카메라 위치를 빼기"뿐이므로 직접 계산해 볼 수 있습니다.

```js
// 회전 없는 카메라: 뷰 좌표 = 월드 좌표 − 카메라 위치
const cameraPos = [2, 0, 5];                        // 카메라의 월드 위치 (오른쪽으로 2 옮김)
const objectWorld = [0, 0, 0];                      // 물체의 월드 위치 (원점)
const objectView = objectWorld.map(                 // 각 성분(x, y, z)마다
  (v, i) => v - cameraPos[i]                        // 물체 위치에서 카메라 위치를 뺀다 (= T⁻¹ 적용)
);                                                  // 결과 배열을 objectView에 저장
console.log(objectView);                            // [-2, 0, -5]: 카메라 기준 왼쪽 2, 앞쪽 5
```

강의 페이지의 [뷰 변환 데모](https://cg.catholic.ac.kr/~mgchoi/CG/demos/d04-view.html)에서 카메라를 움직이면, 오른쪽 그림에서 **세계가 반대로** 움직이는 것을 볼 수 있습니다.

## 3. `lookAt` — "어디서 어디를 볼지"로 카메라 만들기

회전 각도를 직접 계산하기는 어렵습니다. 대신 다음 세 가지만 정하면 됩니다.

| 인자 | 뜻 | 예 |
|---|---|---|
| `eye` | 카메라의 월드 위치 | `[0, 2, 8]` |
| `target` | 바라볼 월드 위치 | `[0, 0, 0]` |
| `up` | "대략 위쪽"의 기준 방향 | `[0, 1, 0]` |

```js
// gl-matrix 라이브러리 사용 예 (강의 코드)
const eye = [0, 2, 8];               // 카메라를 위로 2, 앞으로 8 위치에 둔다
const target = [0, 0, 0];            // 원점을 바라본다
const up = [0, 1, 0];                // 세상의 위쪽은 +y
mat4.lookAt(view, eye, target, up);  // 결과 뷰 행렬 V를 view에 저장 (gl-matrix는 V 자체를 반환)
```

### 3-1. lookAt 안에서 일어나는 일 — 서로 수직인 카메라 축 3개 만들기

$e$ = eye, $t$ = target이라고 하겠습니다.

$$\hat z = \frac{e - t}{\|e - t\|}, \qquad \hat x = \frac{up \times \hat z}{\|up \times \hat z\|}, \qquad \hat y = \hat z \times \hat x$$

1. **$\hat z$**: target에서 eye로 향하는 방향입니다. 카메라는 −z를 보므로, 바라보는 방향의 **반대**가 +z입니다.
2. **$\hat x$** (오른쪽): `up`과 $\hat z$의 **외적**입니다. 외적은 두 벡터 모두에 수직인 벡터를 줍니다.
3. **$\hat y$** (진짜 위쪽): $\hat z \times \hat x$입니다. `up`은 "대략 위"라는 힌트일 뿐이고, 실제 카메라의 y축은 이렇게 다시 계산합니다.

$$V = \begin{bmatrix}
\hat x_x & \hat x_y & \hat x_z & -\hat x \cdot e\\
\hat y_x & \hat y_y & \hat y_z & -\hat y \cdot e\\
\hat z_x & \hat z_y & \hat z_z & -\hat z \cdot e\\
0 & 0 & 0 & 1
\end{bmatrix}$$

각 행은 "(점 − 카메라 위치)를 카메라 축에 **내적**"하는 계산입니다. 내적은 "그 방향으로 얼마나 가 있는가"를 재는 도구입니다(2주차).

직접 구현하면 다음과 같습니다. `camera-study.html`에 들어 있는 코드와 같습니다.

```js
function sub(a, b) { return [a[0]-b[0], a[1]-b[1], a[2]-b[2]]; }   // 벡터 빼기 a − b
function dot(a, b) { return a[0]*b[0] + a[1]*b[1] + a[2]*b[2]; }  // 내적: 한 벡터가 다른 방향으로 얼마나 뻗었나
function cross(a, b) {                                              // 외적: a, b 모두에 수직인 벡터
  return [a[1]*b[2] - a[2]*b[1],                                    //   x 성분
          a[2]*b[0] - a[0]*b[2],                                    //   y 성분
          a[0]*b[1] - a[1]*b[0]];                                   //   z 성분
}                                                                   // cross 끝
function normalize(v) {                                             // 길이를 1로 맞추기 (방향만 남김)
  const len = Math.hypot(v[0], v[1], v[2]);                         //   벡터 길이 √(x²+y²+z²)
  return [v[0]/len, v[1]/len, v[2]/len];                            //   각 성분을 길이로 나눔
}                                                                   // normalize 끝

function lookAt(eye, target, up) {                                  // 뷰 행렬 V를 만든다
  const z = normalize(sub(eye, target));                            // 카메라 +z: target → eye 방향
  const x = normalize(cross(up, z));                                // 카메라 +x(오른쪽): up × z
  const y = cross(z, x);                                            // 카메라 +y(위쪽): z × x (이미 길이 1)
  const m = new Float32Array(16);                                   // 4×4 = 16칸, WebGL은 '열 우선' 저장 (m[열*4+행])
  m[0] = x[0]; m[4] = x[1]; m[8]  = x[2];                           // 1행 = 카메라 x축
  m[1] = y[0]; m[5] = y[1]; m[9]  = y[2];                           // 2행 = 카메라 y축
  m[2] = z[0]; m[6] = z[1]; m[10] = z[2];                           // 3행 = 카메라 z축
  m[12] = -dot(x, eye);                                             // 1행 4열: 카메라 위치를 빼는 효과
  m[13] = -dot(y, eye);                                             // 2행 4열
  m[14] = -dot(z, eye);                                             // 3행 4열
  m[15] = 1;                                                        // 4행 4열 (나머지 4행은 0)
  return m;                                                         // 완성된 V
}                                                                   // lookAt 끝
```

> **열 우선(column-major)이 뭔가요?** 수학 책에서는 행렬을 한 줄(행)씩 읽지만, WebGL은 16칸 배열에 **한 열씩** 넣습니다.
> 그래서 4번째 열에 있는 이동량이 `m[12], m[13], m[14]`에 들어갑니다.

### 3-2. 조심할 점

| 문제 | 이유 | 해결 |
|---|---|---|
| `eye == target` | 방향 $e - t$의 길이가 0이라 나눌 수 없음 | 항상 거리를 두기 |
| `up`이 시선과 평행 (바로 위·아래를 봄) | `up × z` = 0이라 오른쪽 축을 정할 수 없음 | 궤도 카메라의 상하 각도를 **±89°** 안으로 제한 |
| 다른 라이브러리의 `lookAt` | 카메라 **월드 행렬 C**를 반환하는 라이브러리도 있음 | 그런 경우 역행렬이 필요. 이 수업은 **gl-matrix** 기준 (V를 반환) |

## 4. 투영 — 보이는 공간 정하기

뷰 행렬이 "어디서 볼까"를 정했다면, 투영 행렬은 **"그 기준에서 어느 공간을 화면에 담을까"** 를 정합니다.
이 공간을 **시야 공간(view volume)** 이라고 합니다. 이 공간 밖은 잘려서 보이지 않습니다.

| | 직교 투영 (orthographic) | 원근 투영 (perspective) |
|---|---|---|
| 시야 공간 모양 | **직육면체** (상자) | **절두체** (frustum, 꼭대기를 자른 피라미드) |
| 투영선 | 서로 **평행** | **눈 한 점에 모임** |
| 같은 크기 물체 | 거리와 상관없이 **같은 크기** | **멀수록 작게** |
| 쓰임 | 치수 비교, 설계도·평면도 | 실제 눈으로 보는 듯한 화면, 게임 |
| 설정값 | left, right, bottom, top, near, far | fovy(시야각), aspect(화면비), near, far |

- `near`, `far`는 카메라에서 **−z 방향으로 잰 양수 거리**입니다. 실제 평면의 위치는 $z = -near$, $z = -far$입니다.
- 원근 투영에서는 반드시 $0 < near < far$여야 합니다.
- 강의의 [투영 데모](https://cg.catholic.ac.kr/~mgchoi/CG/demos/d04-projection.html)와 이 폴더의 `camera-study.html`에서 직접 비교해 보세요.

## 5. 직교 투영 자세히

### 5-1. 아이디어: 상자를 −1~1 정육면체로 늘이고 줄이기

좌우 $[l, r]$, 상하 $[b, t]$, 깊이 $[-f, -n]$ 범위의 상자를 NDC의 $[-1, 1]^3$ 정육면체에 맞춥니다.
방법은 **구간의 중심을 빼고, 반폭으로 나누기**입니다.

$$x_{ndc} = \frac{2x_v - (r+l)}{r-l}, \qquad y_{ndc} = \frac{2y_v - (t+b)}{t-b}$$

$$P_{ortho} = \begin{bmatrix}
\frac{2}{r-l} & 0 & 0 & -\frac{r+l}{r-l}\\
0 & \frac{2}{t-b} & 0 & -\frac{t+b}{t-b}\\
0 & 0 & -\frac{2}{f-n} & -\frac{f+n}{f-n}\\
0 & 0 & 0 & 1
\end{bmatrix}$$

- 마지막 행이 `[0 0 0 1]`이므로 $w_c = 1$입니다. 나눗셈을 해도 값이 그대로입니다.
- $x_{ndc}$ 계산에 **z가 들어가지 않습니다**. 그래서 멀어져도 크기가 같습니다.
- 그렇다고 깊이가 사라지는 것은 아닙니다. z는 클리핑과 **깊이 테스트**(앞뒤 가리기)에 계속 쓰입니다.

### 5-2. 강의 예제로 직접 계산

좌우 −4~4, 상하 −2~2, near 2, far 10인 상자 안의 점 A `(2, 1, −6)`을 변환해 보겠습니다.

```js
// 직교 투영 공식을 한 성분씩 계산해 보기
const [l, r, b, t, n, f] = [-4, 4, -2, 2, 2, 10];  // 상자 범위: 좌, 우, 아래, 위, near, far
const [x, y, z] = [2, 1, -6];                      // 점 A의 뷰 좌표 (카메라 앞 6)
const xn = (2 * x - (r + l)) / (r - l);            // (4 − 0) / 8 = 0.5
const yn = (2 * y - (t + b)) / (t - b);            // (2 − 0) / 4 = 0.5
const zn = (-2 * z - (f + n)) / (f - n);           // (12 − 12) / 8 = 0 → near(−1)과 far(+1)의 정확히 중간
console.log(xn, yn, zn);                           // 0.5 0.5 0 (w=1이므로 클립 좌표 = NDC)
```

| 뷰 좌표의 경계 | NDC 경계 |
|---|---|
| 왼쪽 x = −4 / 오른쪽 x = 4 | x = −1 / x = +1 |
| 아래 y = −2 / 위 y = 2 | y = −1 / y = +1 |
| near z = −2 / far z = −10 | z = −1 / z = +1 |

> 장면의 모든 점을 억지로 −1~1에 밀어 넣는 것이 아닙니다. 상자 **밖**에 있는 부분은 클리핑으로 버려집니다.

### 5-3. 화면 비율(aspect)에 맞추기

```js
const aspect = canvas.width / canvas.height;     // 화면 비율 (예: 1600/900 ≈ 1.78)
const halfHeight = 4;                            // 화면 세로에 담을 범위의 절반 → 세로 8 월드 단위
mat4.ortho(proj,                                 // 결과를 proj에 저장
  -halfHeight * aspect, halfHeight * aspect,     // 좌우 범위 = 세로 범위 × 화면비 → 원이 타원으로 찌그러지지 않음
  -halfHeight, halfHeight,                       // 상하 범위
  0.1, 100);                                     // near, far
```

- **직교 투영에서 확대·축소** = `halfHeight`를 줄이거나 늘리기
- 직교 투영에서 카메라를 앞으로 옮기기만 하면 물체 크기는 **그대로**입니다. near·far에 대한 위치만 달라집니다.
- 정면·측면·평면(위에서 본 모습)처럼 **여러 직교 뷰를 함께** 보여 주면 구조를 정확히 읽을 수 있습니다. 건축 도면이 이 방식입니다.

## 6. 원근 투영 자세히

### 6-1. 멀리 있는 물체가 작아지는 이유 — 닮은 삼각형

눈에서 물체로 선을 그어 화면과 만나는 점을 생각해 보세요.
같은 높이 H의 물체가 거리 d와 2d에 있으면, 화면에 맺힌 높이는 **절반**이 됩니다. **화면상 높이는 깊이에 반비례합니다.**

수직 시야각을 $\theta$(fovy), 화면 비율을 $a$, $s = 1/\tan(\theta/2)$라고 하면 다음과 같습니다.

$$x_{ndc} = \frac{s}{a}\,\frac{x_v}{-z_v}, \qquad y_{ndc} = s\,\frac{y_v}{-z_v}$$

**깊이($-z_v$)로 나누는** 부분이 핵심입니다. 그런데 행렬 곱셈은 더하기와 곱하기만 할 수 있어서 나눗셈을 직접 하지 못합니다.
그래서 행렬은 **w에 $-z_v$를 담아 두고**, 나눗셈은 GPU의 **원근 나눗셈** 단계에 맡깁니다.

$$P_{persp} = \begin{bmatrix}
\frac{s}{a} & 0 & 0 & 0\\
0 & s & 0 & 0\\
0 & 0 & -\frac{f+n}{f-n} & -\frac{2fn}{f-n}\\
0 & 0 & -1 & 0
\end{bmatrix}$$

- 4행 `[0 0 −1 0]` → $w_c = -z_v$ (깊이)
- **행렬 곱 + 원근 나눗셈**이 함께 원근 효과를 만듭니다.
- WebGL의 NDC 깊이는 −1~1이며, near는 −1, far는 +1로 갑니다.

### 6-2. 강의 예제로 직접 계산

FOV 90°, aspect 1, near 1, far 9일 때 점 A `(1, 1, −3)`을 변환해 보겠습니다.

```js
const fovy = 90 * Math.PI / 180;                   // 시야각 90°를 라디안으로 (삼각함수는 라디안을 씀)
const [a, n, f] = [1, 1, 9];                       // aspect, near, far
const s = 1 / Math.tan(fovy / 2);                  // 1 / tan(45°) = 1
const [x, y, z] = [1, 1, -3];                      // 점 A의 뷰 좌표 (카메라 앞 3)
const xc = (s / a) * x;                            // 클립 x = 1
const yc = s * y;                                  // 클립 y = 1
const zc = -(f + n) / (f - n) * z - 2 * f * n / (f - n); // 클립 z = 3.75 − 2.25 = 1.5
const wc = -z;                                     // 클립 w = 3 (= 카메라에서의 깊이)
console.log([xc, yc, zc, wc]);                     // [1, 1, 1.5, 3] ← 아직 −1~1이 아님!
console.log([xc / wc, yc / wc, zc / wc]);          // [0.333, 0.333, 0.5] ← w로 나눈 뒤가 NDC
```

far 평면의 오른쪽 위 꼭짓점 `(9, 9, −9)`는 클립 `(9, 9, 9, 9)`가 되고, w=9로 나누면 `(1, 1, 1)`입니다. NDC 정육면체의 꼭짓점에 정확히 도착합니다.
**멀수록 넓어지는 절두체가, 깊이로 나눈 뒤에는 똑같은 정육면체가 됩니다.** 그래서 먼 물체가 작게 보입니다.

> **NDC는 픽셀 좌표가 아닙니다.** 순서는 시야 공간 → 클립 좌표 → (클리핑) → 원근 나눗셈 → NDC → **뷰포트 변환** → 픽셀입니다.
> NDC z(−1~1)는 기본 설정에서 깊이 버퍼 값 0~1로 바뀝니다.

### 6-3. 절두체의 크기

카메라에서 깊이 d만큼 떨어진 단면의 **반높이**와 **반폭**은 다음과 같습니다.

$$h(d) = d\,\tan(\theta/2), \qquad w(d) = a\,h(d)$$

```js
mat4.perspective(proj,                  // 결과를 proj에 저장
  60 * Math.PI / 180,                   // fovy: 수직 시야각 60° (반드시 라디안으로!)
  canvas.width / canvas.height,         // aspect: 화면 비율
  0.1, 100);                            // near, far
```

이 공식은 과제에서 **"명판이 화면을 적당히 채우려면 얼마나 떨어져야 하나"** 를 계산할 때 그대로 쓰입니다(8-5절).

### 6-4. 시야각(FOV) 바꾸기 ≠ 카메라 이동

| 조작 | 바뀌는 행렬 | 관찰 결과 |
|---|---|---|
| 눈 위치 고정, **FOV 줄이기** | 투영 행렬 P | 좁은 범위를 확대. 물체끼리의 화면 크기 **비율은 유지** (사진을 잘라서 키운 것과 같음) |
| FOV 고정, **카메라 전진** | 뷰 행렬 V | 각 물체까지의 깊이가 달라져 **가까운 물체가 훨씬 더 커짐** |
| **near만** 변경 | 클리핑·깊이 매핑 | FOV가 같으면 남아 있는 물체의 x·y 크기는 그대로 |

"멀리서 좁은 화각"으로 찍으면 뒤쪽 물체가 상대적으로 커 보입니다. 이것을 **원근 압축**이라고 합니다. 망원 렌즈 사진이 그렇습니다.

### 6-5. near·far는 장면에 맞게

원근 투영의 깊이 값은 거리에 **고르게 배분되지 않습니다**. 가까운 쪽에 정밀도가 몰립니다.
near를 너무 작게(예: 0.0001), far를 너무 크게(예: 1000000) 잡으면 먼 표면끼리 앞뒤 구별이 안 되어 깜빡이는 **Z-fighting**이 생깁니다.
→ **장면이 잘리지 않는 범위에서 near는 가능한 크게, far는 필요한 만큼만** 정하세요.

### 8-3. 왜 O1·O2에는 직교 뷰가 필요한가

원근 화면에서는 같은 크기라도 거리에 따라 다르게 보입니다. 비스듬히 보면 높이와 깊이 차이가 섞입니다.
→ **축에 정렬한 직교 뷰**에서 거리의 영향을 없애고 모서리를 비교해야 합니다. 투영만 직교로 바꾸고 카메라를 비스듬히 두면 소용이 없습니다.

| 뷰 | 카메라 위치·방향 | 화면 축 | 비교할 것 |
|---|---|---|---|
| 전면 직교 (O1) | 건물 앞 **+z**에서 **−z**를 봄, up = +y | 가로 = x, 세로 = y | 두 패널 위 모서리가 같은 수평선인가, 폭이 같은가 |
| 오른쪽 측면 직교 (O2) | 건물 오른쪽 **+x**에서 **−x**를 봄, up = +y | 가로 = z (+z는 화면 **왼쪽**), 세로 = y | 두 장치의 +z 끝이 같은 수직선인가 |

> 두 물체를 **같은 화면**에서 비교하거나, 화면이 나뉘어 있다면 **같은 배율**(월드 1m당 픽셀 수)을 써야 합니다.
> 대상마다 자동으로 확대된 화면 두 장을 비교하면 실제 크기 비교가 되지 않습니다.

```js
const viewer = window.InspectionViewer;                         // 시작 코드가 만들어 둔 뷰어 객체

// 표지 p를 정면에서, 화면의 fill(60%)을 채우도록 보는 카메라를 계산한다
function signCamera(p, fovDeg = 45, fill = 0.6, aspect = 1) {   // p: model.poi의 한 항목, aspect: 그릴 화면 영역의 가로/세로
  const [w, h] = p.size;                                         // 표지의 실제 폭·높이 (m)
  const need = Math.max(h, w / aspect) / fill;                   // 화면 세로 방향에 담아야 할 높이 (가로가 넘치지 않게 w/aspect도 고려)
  const dist = need / (2 * Math.tan(fovDeg * Math.PI / 360));    // 화면 높이 = 2·d·tan(θ/2) → d = 높이 / (2·tan(θ/2))
  const normal = [Math.sin(p.yaw), 0, Math.cos(p.yaw)];          // 표지 앞면이 향하는 방향 (+z를 yaw만큼 y축 회전)
  const eye = p.position.map((v, i) => v + normal[i] * dist);    // eye는 표지 위치에서 앞면 방향으로 dist만큼 떨어진 곳
  return { eye, target: [...p.position], up: [0, 1, 0], fov: fovDeg }; // target = 표지 중심, up = 세상의 위쪽
}                                                                 // signCamera 끝
```

- 큰 안내판(P1, 폭 2m)은 멀리서, 작은 명판(P3, 폭 0.28m)은 가까이서 보게 됩니다. **대상 크기에 맞춰 거리가 자동으로 정해집니다.**
- eye 근처에 벽이 있으면 가려질 수 있습니다(가림). 너무 가까우면 near에 잘립니다(near 클리핑). 이 둘을 구분해서 대응하세요.

**(2) 4분할 뷰: 자유 시점 + 표지 확대 + 전면 직교 + 측면 직교**

```js
let current = viewer.model.poi[0];                               // 지금 보고 있는 표지 (버튼 등으로 바꾸게 만들면 됨)

viewer.render = (v) => {                                         // 기본 한 화면 그리기를 이 함수로 대체
  const W = v.canvas.width, H = v.canvas.height;                 // 그리기 버퍼의 실제 픽셀 크기
  const hw = Math.floor(W / 2), hh = Math.floor(H / 2);          // 화면을 반으로 나눌 위치
  // viewport = [x, y, 폭, 높이], 원점은 '왼쪽 아래'
  v.drawView(v.controls.camera(), [0, hh, hw, H - hh]);          // 왼쪽 위: 기존 트랙볼 원근 뷰 (전체 맥락)
  v.drawView(signCamera(current, 45, 0.6, (W - hw) / (H - hh)),  // 오른쪽 위: 선택한 표지 확대 (그 영역의 aspect 전달)
             [hw, hh, W - hw, H - hh]);                          //   오른쪽 위 영역
  v.drawView({ eye: [3, 4, 60], target: [3, 4, 0], up: [0, 1, 0], // 왼쪽 아래: 전면 직교 (+z에서 −z를 봄) → O1
               orthographic: true, halfHeight: 6 },              //   세로 12m를 담음
             [0, 0, hw, hh]);                                    //   왼쪽 아래 영역
  v.drawView({ eye: [60, 4, 0], target: [0, 4, 0], up: [0, 1, 0], // 오른쪽 아래: 오른쪽 측면 직교 (+x에서 −x를 봄) → O2
               orthographic: true, halfHeight: 6 },              //   전면과 같은 halfHeight → 두 뷰의 배율이 같음
             [hw, 0, W - hw, hh]);                               //   오른쪽 아래 영역
};                                                               // render 끝
```

- `drawView`는 각 영역의 `폭/높이`로 aspect를 계산하므로 각 뷰가 찌그러지지 않습니다.
- 직교 뷰의 eye는 멀리 두어도 크기가 변하지 않습니다(5-3절). 건물 전체가 near·far 사이에 들어가는지만 확인하면 됩니다.
- 4분할에서는 화면 하나하나가 작아져 글자가 읽기 어려울 수 있습니다. 강의에서도 이 점을 함께 고민하라고 합니다. 확대 화면을 크게 하는 등 본인의 사용자에 맞게 조정하세요.

## 9. 자주 하는 실수

| 증상 | 확인할 것 |
|---|---|
| 아무것도 안 보임 | 물체가 카메라 **앞**(뷰 z < 0)에 있나? near~far 사이인가? eye == target은 아닌가? |
| 물체가 찌그러짐 | 투영에 `canvas.width / canvas.height`를 넣었나? 창 크기가 바뀔 때 다시 계산하나? |
| 물체가 너무 크거나 작게 보임 | FOV를 **라디안**으로 넣었나? (`60`이 아니라 `60 * Math.PI / 180`) |
| 위·아래가 뒤집힘, 화면이 튐 | up이 시선과 평행하지 않나? (바로 위나 아래를 보는 경우) |
| 먼 면이 깜빡임 (Z-fighting) | near가 너무 작거나 far가 너무 크지 않나? |
| 가까이 가면 물체가 잘림 | near 클리핑입니다. near를 줄이거나 카메라를 뒤로 빼세요 |
| 행렬 순서가 헷갈림 | `P * V * M * 위치`이고, 오른쪽부터 적용됩니다 |
| 결과가 두 번 나눈 것처럼 이상함 | 셰이더에서 `gl_Position`을 직접 w로 나누지 않았나? |

## 10. 용어 정리

| 용어 | 뜻 |
|---|---|
| 뷰 행렬 V | 월드 좌표를 카메라 기준 좌표로 바꾸는 행렬. 카메라 배치 행렬의 역행렬 |
| 투영 행렬 P | 시야 공간을 클립 좌표로 바꾸는 행렬 |
| 시야 공간 (view volume) | 화면에 담길 3D 공간. 직교는 상자, 원근은 절두체 |
| 절두체 (frustum) | 피라미드의 꼭대기를 잘라낸 모양 |
| 클립 좌표 | `gl_Position`의 값 (x, y, z, w). 클리핑에 사용 |
| 클리핑 | 시야 공간 밖을 잘라내는 일 ($-w \le x,y,z \le w$) |
| 원근 나눗셈 | x, y, z를 w로 나누는 일. 원근 투영에서는 w = 깊이 |
| NDC | 정규화 장치 좌표. 모든 축이 −1~1인 정육면체 |
| 뷰포트 변환 | NDC를 실제 화면 픽셀로 바꾸는 일 (`gl.viewport`) |
| FOV (fovy) | 수직 시야각. 클수록 넓게 보이고 물체는 작아짐 |
| aspect | 화면 비율 = 가로 / 세로 |
| near / far | 보이는 깊이의 앞·뒤 경계 (카메라에서 잰 양수 거리) |
| Z-fighting | 깊이 정밀도가 부족해 두 면이 번갈아 보이며 깜빡이는 현상 |

## 11. 스스로 점검

1. 카메라가 `(0, 0, 5)`에서 원점을 볼 때, 원점에 있는 물체의 뷰 좌표는? → `(0, 0, −5)`
2. 카메라를 +x로 3 옮기면 화면 속 물체는 어느 쪽으로 움직이나? → 왼쪽 (−x)
3. 왜 V = C⁻¹인가? → C는 카메라 좌표를 월드로 보내므로, 반대 방향(월드 → 카메라)은 그 역행렬이다
4. 직교 투영에서 물체를 확대하려면? → halfHeight(상하 범위)를 줄인다. 카메라를 다가가게 하는 것으로는 안 된다
5. 원근 투영에서 w에는 무엇이 들어가나? → $-z_v$, 즉 카메라에서의 깊이
6. FOV를 줄이는 것과 카메라를 전진시키는 것의 차이는? → FOV 축소는 크기 비율을 유지한 채 확대하고, 전진은 가까운 물체를 더 크게 키운다
7. 4분할 뷰에서 각 뷰의 aspect는? → 전체 캔버스가 아니라 **그 뷰 영역**의 폭/높이
