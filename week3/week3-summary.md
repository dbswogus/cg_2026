> **한 줄 요약**: 3D 모델은 **숫자 배열(버퍼)** 이고, GPU는 그 숫자를 **정점마다(버텍스 셰이더)**, **픽셀마다(프래그먼트 셰이더)** 같은 계산을 동시에 반복해서 화면을 만든다. 우리가 직접 쓰는 건 이 두 셰이더다.

## 0. 좌표계 약속

- 3주차부터는 **y-up, 오른손 좌표계**를 씁니다(OpenGL·WebGL 기준). 2주차 도구는 z-up이었습니다.
- 오른손 좌표계: $\hat x\times\hat y=\hat z$. DirectX·Unity는 왼손 좌표계입니다.
- 모델이 누워 보이거나 뒤집혀 보이면 **좌표계 약속부터 의심**하세요. AI가 준 코드에도 자주 섞여 들어옵니다.

## 1. 메시 = 숫자 배열

| 버퍼 | 정점당 값 | 뜻 |
|---|---|---|
| 위치 | x, y, z | 어디에 있나 (필수) |
| 법선 | nx, ny, nz | 표면이 어느 쪽을 향하나 (조명에 필수) |
| 색 | r, g, b | 정점 색 |
| UV | u, v | 그림의 어느 지점인가 |
| 인덱스 | 삼각형마다 번호 3개 | 어느 정점끼리 잇나 |

- **왜 삼각형인가?** 세 점은 항상 한 평면 위에 있어서 면의 방향이 하나로 정해집니다.
- 인덱스 버퍼를 쓰면 정점을 재사용해 메모리를 줄일 수 있습니다. 다만 정육면체처럼 면마다 법선이 다르면 꼭짓점 8개를 24개로 나눠 저장합니다.
- 분할 수를 2배로 하면 정점은 약 4배가 됩니다. 눈에 안 보이는 정밀도는 낭비라서, 거리에 따라 모델 상세도를 바꾸는 **LOD**를 씁니다.

## 2. CPU vs GPU

| | CPU | GPU |
|---|---|---|
| 잘하는 것 | 복잡한 일 하나를 빠르게 | **같은 일**을 한꺼번에 많이 |
| 코어 | 적고 강함 | 작은 코어 수천 개 |
| `if` 분기 | 강함 | 약함 |

- 정점 변환과 픽셀 색칠은 서로 결과가 필요 없는 **데이터 병렬** 계산이라 GPU에 딱 맞습니다.
- 비유: 미적분 한 문제는 교수(CPU)가, 곱셈 백만 개는 학생 천 명(GPU)이 빠릅니다. **셰이더 = 학생 한 명이 할 일을 적은 것**입니다.

## 3. 그래픽스 파이프라인

```text
버퍼 → ② 버텍스 셰이더 → 삼각형 조립 → 클리핑 → 원근 나눗셈·뷰포트
     → ⑥ 래스터화 → ⑦ 프래그먼트 셰이더 → 깊이·혼합 검사 → 화면
```

- 직접 쓰는 단계는 **②와 ⑦뿐**입니다. 나머지는 GPU의 고정 회로가 처리합니다.
- ②는 **정점 수만큼**(삼각형 하나면 3번) 실행됩니다.
- ⑦은 **픽셀 수만큼**(수십만 번) 실행됩니다. 개수가 폭발하는 곳은 ⑥ 래스터화이고, 그래서 **프래그먼트 셰이더가 무거우면 훨씬 느려집니다.**
- 그래픽 프로그램은 **프로그램 3개**로 이루어집니다.
  - 메인 (JavaScript, CPU): 버퍼 준비, 셰이더 컴파일, uniform 전달, 그리기 명령
  - 버텍스 셰이더 (GLSL, GPU): `gl_Position`을 반드시 써야 함
  - 프래그먼트 셰이더 (GLSL, GPU): 픽셀 색을 출력
- `gl.drawElements(...)` 한 줄이 파이프라인 전체를 돌립니다. 반복문은 GPU가 알아서 처리합니다.

## 4. 데이터가 들어오는 세 통로

| 키워드 | 뜻 | 예 |
|---|---|---|
| `in` | 정점마다 다른 값 (버퍼) / 버텍스 셰이더에서 보간되어 온 값 | `aPos`, `vNormal` |
| `out` | 다음 단계로 보낼 값 | `vColor`, `fragColor` |
| `uniform` | 한 번의 그리기 동안 **모든 정점·픽셀이 같은 값** | `uTime`, `uModel` |

```glsl
// 버텍스 셰이더
#version 300 es
layout(location=0) in vec3 aPos;       // 정점 위치 (버퍼 0번)
layout(location=1) in vec3 aNormal;    // 정점 법선 (버퍼 1번)
uniform mat4 uModel, uViewProj;        // 모든 정점이 같은 행렬을 받음
out vec3 vNormal;                      // 프래그먼트 셰이더로 보낼 법선
void main() {
  vNormal = mat3(uModel) * aNormal;    // 법선은 회전만 (3×3: 이동은 방향에 적용하면 안 됨)
  gl_Position = uViewProj * uModel * vec4(aPos, 1.0); // 최종 위치 (오른쪽부터 적용)
}
```

## 5. 보간 — 정점 사이 값은 GPU가 만든다

- 버텍스 셰이더의 `out` 값은 삼각형 안쪽 픽셀에서 **세 꼭짓점 값을 거리 비율로 섞어서** 프래그먼트 셰이더의 `in`으로 들어옵니다.
- 꼭짓점이 빨강·초록·파랑이면 안쪽이 무지개처럼 섞이는 이유입니다.
- 보간된 법선은 길이가 1이 아닐 수 있으므로 **프래그먼트 셰이더에서 다시 `normalize`** 해야 합니다.

## 6. GLSL 핵심 함수 — 무늬를 만드는 도구

| 함수 | 하는 일 | 쓰는 곳 |
|---|---|---|
| `mix(a, b, t)` | t = 0이면 a, 1이면 b, 그 사이는 비율대로 섞기 | 두 색 섞기 |
| `step(e, x)` | x < e면 0, 아니면 1 | 딱 끊어지는 경계 |
| `smoothstep(a, b, x)` | a~b 사이에서 0 → 1로 **부드럽게** | 부드러운 경계 |
| `sin(x)` | −1~1로 반복 | 줄무늬, 물결 |
| `fract(x)` | 소수 부분만 (0~1 반복) | 격자, 반복 무늬 |
| `floor(x)` | 정수 부분 | 칸 번호 |
| `distance(a, b)` | 두 점 사이 거리 | 원, 동심원 |
| `dot`, `normalize` | 내적, 길이를 1로 | 조명 |
| `clamp`, `abs`, `pow` | 자르기, 절댓값, 거듭제곱 | 값 다듬기 |

- GLSL은 **실수에 소수점이 필요**합니다. `1`이 아니라 `1.0`으로 써야 합니다(int/float 혼용 오류).

## 7. 확산 반사 — 가장 단순한 조명

$$\text{밝기} = \max(N\cdot L,\ 0)$$

- 빛을 비스듬히 받으면 같은 빛이 넓게 퍼져 어두워집니다. 그 비율이 $\cos\theta$이고, N·L이 둘 다 단위벡터면 내적 한 번으로 구할 수 있습니다.
- `max(…, 0.0)`: 빛을 등진 면은 내적이 음수가 되어 밝기가 마이너스가 되므로 0으로 자릅니다. → **밤**
- 확산 반사는 **보는 방향과 무관**합니다. 카메라를 돌려도 밝기가 그대로입니다.

```glsl
vec3 N = normalize(vNormal);                // 보간된 법선 다시 정규화
vec3 L = normalize(vec3(0.45, 0.8, 0.35));  // 광원 쪽 방향
float diff = max(dot(N, L), 0.0);           // 0(밤) ~ 1(정면으로 받음)
fragColor = vec4(vColor * (0.15 + 0.85 * diff), 1.0); // 15%는 주변광으로 남겨 밤도 조금 보이게
```

- 규칙
  - **이미지 파일 금지**
  - 서로 다른 행성 **2개 이상**
  - `uTime`으로 움직이는 것 하나 이상

- 예시 3개(가스·바위·위성)는 그대로 내면 인정되지 않습니다. **모든 줄을 설명할 수 있어야** 합니다.

- 보고서에는 **의도**(무엇을, 왜)와 **방법**(식과 그 식이 왜 그런 무늬가 되는지, 요소당 3~4줄)을 쓰고, 시행착오도 적습니다.

## 9. 자주 하는 실수

| 증상 | 원인 |
|---|---|
| 셰이더 컴파일 오류 | `1` 대신 `1.0`, `#version 300 es`가 첫 줄이 아님, `in`/`out` 이름 불일치 |
| 아무것도 안 보임 | 좌표가 −1~1 밖, `useProgram` 전에 uniform 설정, 그리기 호출 누락 |
| 뒤쪽 면이 앞을 덮음 | `gl.enable(gl.DEPTH_TEST)`와 깊이 버퍼 초기화 누락 |
| 무늬가 행성과 같이 안 돎 | 무늬를 세계 기준 법선(`vNormal`)으로 계산함 → `vSurf` 사용 |
| 조명이 얼룩덜룩 | 보간된 법선을 다시 `normalize` 하지 않음 |
| 모델이 누워 있음 | z-up / y-up 혼용 |
